=============================================================================
ACCESSING THE API
=============================================================================

{{- if .Values.api.ingress.enabled }}
The API is accessible via Ingress:
{{- range .Values.api.ingress.hosts }}
  http{{ if $.Values.api.ingress.tls }}s{{ end }}://{{ .host }}
{{- end }}
{{- else if eq .Values.api.service.type "LoadBalancer" }}
Get the LoadBalancer IP:
  kubectl get svc {{ include "cube3d.fullname" . }}-api -n {{ .Release.Namespace }} -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
{{- else }}
Port-forward to access the API:
  kubectl port-forward svc/{{ include "cube3d.fullname" . }}-api {{ .Values.api.service.port }}:{{ .Values.api.service.port }} -n {{ .Release.Namespace }}

Then access at: http://localhost:{{ .Values.api.service.port }}
{{- end }}

=============================================================================
SCALING
=============================================================================

The GPT stage is the bottleneck. To handle more throughput:

1. Scale GPT Triton pods (each needs 1 GPU):
   kubectl scale deployment {{ include "cube3d.fullname" . }}-triton-gpt --replicas=10

2. Scale GPT workers to match:
   kubectl scale deployment {{ include "cube3d.fullname" . }}-worker-gpt --replicas=10

Or with KEDA enabled, scaling happens automatically based on Temporal queue depth.
